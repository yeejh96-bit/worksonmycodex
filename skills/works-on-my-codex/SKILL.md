# Works on My Codex

루트 `AGENTS.md` 첫 줄에는 다음 철학을 둔다. 사람은 원하는 것과 되돌릴 수 없는 결정만 맡고, 나머지는 모델이 맡는다. `AGENTS.md`에는 자율 실행 원칙, 프로젝트 목적·지속 제약·완료 기준, 작업별 읽기 경로, 공통 검증 방법만 둔다. 구현 세부 사항, 현재 작업, 일회성 계획과 진행 기록은 대화나 일반 프로젝트 문서에 둔다.

세션 시작 훅이 `[WOMC]` 미설치·구버전·프로젝트 드리프트 안내를 출력하면 사용자에게 설치나 갱신 여부를 다시 묻지 말고 첫 요청을 처리하기 전에 이 스킬을 적용합니다. 드리프트 검사는 읽기 경로, 비표준 로컬 스킬, 워크스페이스와 검증 명령의 구조를 현재 하네스와 읽기 전용으로 비교합니다. 일반 문서 본문 수정만으로는 갱신을 요구하지 않습니다. 훅은 파일을 직접 쓰지 않고 필요한 조치만 모델에게 알립니다.

## 작성 전에 살펴보기

프로젝트 루트와 `git status`를 확인한 뒤 디렉터리 구조, 매니페스트, 잠금 파일, 루트의 지속 문서와 `docs/` 문서 후보, 로컬 `SKILL.md`, 테스트 설정, 실행 스크립트, 기존 `AGENTS.md`를 살펴봅니다. README·기여·아키텍처·제품·보안 문서를 우선하고, 이름이 일반적이어도 전체 구현이나 특정 작업 전에 반드시 읽어야 한다고 내용에 명시된 지속 문서를 확인합니다. 회의록·변경 기록·구현 일지는 제외합니다. `.env`, 자격 증명 저장소, 개인 키는 열지 않습니다. 빈 프로젝트와 기존 프로젝트를 구분하고 미커밋 작업을 보존합니다.

비어 있지 않은 루트 `AGENTS.override.md`가 있으면 멈추고, 이 파일이 `AGENTS.md`를 가리는 충돌을 보고합니다. WOMC 철학을 override에 쓰지 않으며, 사용자가 선택한 해결 없이 override를 이동·삭제하지 않습니다.

## 기존 AGENTS.md 다시 짜기

갱신 전에 WOMC 관리 영역 밖의 기존 내용도 다음 기준으로 감사합니다.

- 프로젝트가 무엇을 만드는지 코드만으로 알기 어려운 한 문장을 프로젝트 목적으로 남깁니다.
- 앞으로도 결과를 바꾸는 짧은 제품 원칙, 보안·승인 경계와 프로젝트 수준 완료 기준만 남깁니다.
- 특정 작업에서 읽어야 할 지속적인 문서·로컬 스킬 경로만 남깁니다. 회의록·변경 기록·구현 일지는 라우팅에 자동 추가하지 않습니다.
- 재사용할 수 있고 실제로 실행 가능한 공통 검증만 남깁니다.
- 구현 이력·진행 상황·완료된 일·일회성 지시는 남기지 않습니다.
- 긴 배경·근거·숫자·결정 경위는 프로젝트의 기존 관례에 맞는 `docs/`로 옮기고 `AGENTS.md`에는 해당 작업의 읽기 경로만 둔다.
- 사용자가 만든 스킬과 지역 문서는 보존합니다.
- 작업 중 틀린 가정, 사용할 수 없는 도구, 이 프로젝트에서만 다른 사실을 발견해 이후 결과가 달라진다면 사용자가 따로 요청하지 않아도 적절한 프로젝트 목적·지속 제약·완료 기준·읽기 경로·검증 방법에 반영합니다.

옮기거나 제거할 내용과 대상 파일을 먼저 확인합니다. 기존 내용을 필요한 문서로 옮긴 뒤 `--replace-unmanaged`로 관리 영역 밖을 정리합니다. 분류가 모호하면 제거하지 말고 충돌로 보고합니다.

## 하네스 생성·갱신

루트 `AGENTS.md`의 WOMC 영역은 포함된 `scripts/setup_harness.py`로만 생성합니다. 스크립트 경로는 이 `SKILL.md`를 기준으로 해결합니다.

1. `--dry-run`으로 제안을 미리 보고 실제 프로젝트 구조와 대조합니다.
2. `--project-summary`에는 프로젝트가 무엇을 만드는지 한 문장으로 전달합니다. 코드와 문서로 충분히 알 수 있으면 모델이 작성하고, 빈 프로젝트처럼 목표를 알 수 없을 때만 사용자에게 묻습니다.
3. `--principle`에는 변하지 않는 제품 원칙만, `--done-condition`에는 여러 작업에 계속 적용되는 프로젝트 수준 완료 기준만, `--approval-boundary`에는 지속적인 보안·승인 경계만 전달합니다. 현재 작업과 일회성 인수 조건은 전달하지 않습니다.
4. 파일명만으로 알 수 없는 지속적인 작업별 읽기 경로는 `--route`로 전달합니다.
   - 전체 구현 전에 항상 읽어야 하는 정보는 `전체 프로젝트 구현: \`경로\`를 읽는다`처럼 전역 조건으로 기록합니다.
   - 특정 영역이나 작업에서만 필요한 정보는 해당 조건을 구체적으로 기록합니다.
5. 매니페스트·테스트 설정·CI·프로젝트 문서·사용자를 통해 확인한 안전한 로컬 명령만 `--check-command`으로 전달합니다.
6. 기존 수동 값은 신규 값과 중복 제거해 병합됩니다. 정리할 값을 모두 검토한 뒤에만 해당 `--replace-*` 옵션을 사용합니다.
7. 관리 영역 밖을 이미 감사·이전했을 때만 `--replace-unmanaged`를 사용합니다.
8. 제안을 확인한 뒤 같은 인수로 `--dry-run` 없이 실행하고 diff를 검토합니다.

지속적인 읽기 경로, 워크스페이스 또는 검증 명령을 추가·이동·삭제하거나 역할을 바꾼 작업에서는 같은 작업을 끝내기 전에 하네스를 갱신합니다. Codex가 자동 발견하는 `.codex/skills/`, `.agents/skills/`, 플러그인 `skills/`의 설명은 `AGENTS.md`에 중복하지 않습니다. 비표준 경로의 스킬만 짧은 사용 조건과 진입점을 기록하고, 세부 참고 경로는 스킬 안에 둡니다.

마커가 부분적이거나 중복되면 멈추고 충돌을 보고합니다. 마커를 임의로 지워 복구하지 않습니다. 특정 하위 경로에만 적용되는 지속 제약이나 검증이 있으면 그 경로에 가장 가까운 중첩 `AGENTS.md`를 사용합니다. 단지 저장소가 크다는 이유만으로 중첩 파일을 만들지는 않습니다.

## 설정 검증하기

변경의 영향과 위험에 맞는 최소 충분 검증을 선택합니다. 생성기·체커·하네스 형식을 바꾸면 전체 프로젝트 검증을 실행하고, 문서 표현만 바꾸면 관련된 구조·생성 검사만 선택할 수 있습니다. 정확한 명령과 결과를 보고합니다. 실행할 수 없다면 누락된 실행 파일, 의존성, 서비스, 픽스처, 설정을 구체적으로 보고하고 통과했다고 표현하지 않습니다.

파일이 있다는 이유만으로 Codex가 하네스를 불러왔다고 주장하지 않습니다. 사용자가 실제 탐색 검사를 요청하면 대상 루트에서 읽기 전용 임시 `codex exec`를 실행해 의도한 지침을 보고하는지 확인합니다. 플러그인 개발 중에는 README에 기록된 선택형 통합 테스트를 사용합니다. 두 검사 모두 승인 없이 계정이나 네트워크 자원을 사용하지 않습니다.

웹 프로젝트는 기존 개발 서버와 브라우저/E2E 도구를 우선합니다. 환경에서 브라우저에 접근할 수 있다면 변경된 사용자 흐름과 관련 시각 상태를 검증합니다. 하네스를 표준화하려고 Playwright나 다른 의존성을 설치하지 않습니다.

마지막으로 생성·갱신한 파일, 보존한 충돌·제한, 실행한 정확한 검증 명령과 결과를 나열합니다. 사용자가 구체적으로 요청하지 않으면 커밋·푸시·배포·외부 설치 설정 변경을 하지 않습니다.
