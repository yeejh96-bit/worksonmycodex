# 위임 정책과 검증

이 문서는 위임 정책을 수정하거나 모델 선택·스킬 전달 동작을 검증할 때만 읽는다. 생성기는 [짧은 위임 원칙](../assets/delegation-policy.md)을 `AGENTS.md`에 넣는다. 요청을 자동 분류하거나 에이전트를 실행하지는 않는다.

## 위임할 때 확인할 점

- 작업을 독립된 범위와 완료 기준으로 설명할 수 있고 메인이 병행할 유용한 일이 있는지 살핀다. 전달·대기·검토 부담이 크면 직접 처리한다.
- 현재 환경에서 제공되는 모델·추론 수준·도구 중 작업의 복잡도와 위험에 적합한 조합을 고른다. 특정 모델 세대나 추론 수준을 모든 작업에 고정하지 않는다. 사용자 지정 모델·예산·위임 제한을 우선한다.
- 위임 요청에 목표와 완료 기준, 프로젝트 루트, 읽기·수정 범위, 필요한 `AGENTS.md`와 스킬 진입 경로, 대화에만 있는 사용자 제한을 전달한다. 대화 전체나 도구 접근이 자동으로 공유된다고 가정하지 않는다.
- 권한·도구 부족은 모델 변경으로 해결된다고 가정하지 않는다. 메인은 반환된 근거와 변경분을 확인하고 통합 결과를 검증한다.

이 참고 문서는 프로젝트의 매 작업에서 읽을 필요가 없다. 사용자 정의 에이전트 설정이나 `config.toml`은 생성기가 변경하지 않는다.

## 검증 범위

생성기 테스트는 새 생성·기존 갱신·반복 실행, 사용자 작성 내용과 설정 보존, 기본 승인 문구 이전을 확인한다. `--check` 통과는 파일이 현재 생성 결과와 같다는 뜻이다. 실제 위임 품질이나 모델 선택의 적절성을 증명하지는 않는다.

위임 동작을 별도로 평가할 때는 짧은 단일 작업, 독립적인 조사와 구현, 중요한 검토, 사용자 위임 제한, 모델·도구 접근 불가, 프로젝트 스킬 전달 사례를 구분한다. 판단만 시험했다면 모의 검증으로 보고하고, 실제 에이전트 호출·스킬 사용·최종 결과와 혼동하지 않는다.
