# 프로젝트 환경 감사

## 언제, 어디를 볼지

WOMC 최초 적용, 설치본을 포함한 명시적 WOMC 업데이트, 현재 프로젝트의 명시적 WOMC 하네스 갱신에서 현재 프로젝트를 한 번 감사한다. WOMC 저장소에서 실행해도 같은 절차를 적용한다. 최신 플러그인을 설치하는 업데이트에서는 설치된 새 `SKILL.md`와 이 문서를 다시 읽은 뒤 감사한다. 한 작업 안에서 감사 결과를 반영해 하네스를 갱신하고 검증하면 종료한다. 하네스 변경을 이유로 전체 감사를 다시 시작하지 않는다.

일반 코딩 작업에서 지속 맥락이나 읽기 경로를 바꿔 하네스를 동기화할 때는 전체 환경 감사를 반복하지 않는다. 새로 만들거나 수정한 스킬·지침·도구 연결만 필요한 범위에서 검토한다. 별도의 스킬 정리 요청은 요청한 범위의 스킬을 검토한다.

프로젝트 루트·Git 상태와 사용자 작성 지침을 확인한다. 실제 운영 스킬은 현재 프로젝트의 `.codex/skills/`, `.agents/skills/`, 플러그인 매니페스트가 노출하는 `skills/`, 명시적으로 연결된 프로젝트 스킬 중 실제 진입점으로 판단한다. 다른 프로젝트, 설치된 모든 플러그인, 백업·예제·참고 문서 속 스킬을 운영 스킬 수에 섞지 않는다. 모든 파일을 무작정 열지 말고 진입 설명과 관련 지침부터 읽으며, 충돌 가능성이 있을 때만 상세 참고 문서를 연다.

## 스킬 판단

각 운영 스킬의 실제 사용 상황과 없을 때 잃는 프로젝트 고유 지식·도구·품질 기준을 확인한다. 호출 조건이 너무 넓은지, 일반적인 코딩·계획·테스트 상식을 반복하는지, 루트 `AGENTS.md`나 다른 스킬과 중복·충돌하는지 판단한다. 불필요한 문서 선독, 모든 작업의 전체 테스트, 되돌릴 수 있는 작업의 승인 요구도 확인한다. 스킬 개수·길이나 추정 호출 빈도만으로 결론 내리지 않는다. 근거가 있으면 유지·축소·통합·일반 문서 이동·제거 후보를 정하고 실제 의미 있는 후보만 보고한다.

## 연결 도구 판단

현재 실행에서 실제 보이는 MCP 서버·커넥터·플러그인·외부 도구의 목록과 설명, 필요하면 접근 가능한 읽기 전용 연결 목록을 근거로 판단한다. 현재 프로젝트와의 관련성, 항상 노출되는 도구의 선택 부담, 기능 중복, 실제 사용 근거, 필요할 때만 탐색하거나 더 좁은 도구 집합을 쓸 가능성을 살핀다. 이름이 비슷하다는 이유만으로 중복이라고 단정하지 않는다. 사용 빈도는 확인 가능한 기록이 있을 때만 말한다.

런타임 목록과 설치·활성화 상태는 서로 다른 증거다. 목록이나 설정에 접근할 수 없으면 해당 범위를 `확인 불가`로 보고한다. 보이지 않는 연결의 존재·부재·활성 상태를 추측하지 않으며, 자격 증명이나 비공개 설정을 열거나 권한을 우회하지 않는다. 감사 때문에 새 연결을 설치하지 않는다.

## 반영과 보고

감사만으로 스킬·MCP 서버·플러그인을 삭제하거나 커넥터를 비활성화하지 않는다. 외부 서비스와 사용자 전역 Codex 설정도 바꾸지 않는다. 명백히 중복되거나 낡은 WOMC 관리 영역의 지침은 기존 안전 경계 안에서 정리할 수 있다. 그 밖의 실제 삭제·연결 변경은 기존 승인 경계를 따른다.

감사 결과, 개수, 후보 목록 같은 일회성 상태를 `AGENTS.md`에 쓰지 않는다. 앞으로의 작업에도 영향을 주는 사실만 프로젝트 목적·지속 제약·작업별 읽기 경로에 짧게 반영하고, 긴 설명은 필요할 때 읽는 문서에 둔다. `setup_harness.py`의 `--check`는 하네스 일치 검사일 뿐 감사 완료 증거가 아니다.

완료 보고는 문제 없으면 한 문장으로 끝낸다. 의미 있는 후보가 있으면 위치·이유·실제 영향, 자동으로 바꾸지 않은 이유, 필요한 사용자 선택만 간단히 제시한다. 모든 스킬과 도구를 표로 나열하지 않는다. 확인하지 못한 외부 도구 범위는 `확인 불가`라고 구분한다.
