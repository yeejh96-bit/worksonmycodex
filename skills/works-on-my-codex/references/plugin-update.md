# 설치된 WOMC 자체 최신화

사용자가 “WOMC 업데이트해 줘”, “이 프로젝트 WOMC를 최신화해 줘”처럼 실행을 요청하면 그 요청을 아래 두 로컬 Codex 설정 변경에 대한 승인으로 보고 다시 묻지 않습니다. WOMC 버전이나 업데이트 방법을 질문만 한 경우에는 실행하지 않습니다.

1. `codex plugin marketplace upgrade works-on-my-codex`로 등록된 Git 마켓플레이스 스냅샷을 갱신합니다.
2. 첫 명령이 성공하면 `codex plugin add works-on-my-codex@works-on-my-codex`로 설치된 플러그인을 갱신합니다. 플러그인을 먼저 제거하지 않습니다.
3. `codex plugin list --json`으로 `works-on-my-codex@works-on-my-codex`가 설치·활성화됐고 버전이 `x.x.x` 형식인지 확인합니다. 실패한 단계를 반복하거나 우회하지 말고 구체적인 오류를 보고하며, 성공하지 않은 갱신을 완료로 표현하지 않습니다.
4. 설치 결과에서 최신 플러그인 루트를 확인하고 그 안의 `skills/works-on-my-codex/SKILL.md`를 다시 읽습니다. 최신 스킬에 포함된 `scripts/setup_harness.py`를 사용해 현재 프로젝트 하네스를 `--dry-run`으로 검토한 뒤 갱신하고 diff를 확인합니다. 같은 생성기와 인수에 `--check`를 추가해 하네스가 최신인지 확인합니다.
5. 설치본 버전·활성화 상태, 프로젝트 하네스 검사 결과, 현재 세션의 자동 반영 확인 여부를 구분해 보고합니다. 최신 파일을 직접 읽은 것은 현재 작업에 최신 절차를 적용한 증거이며, 실행 중인 세션의 스킬·도구 목록이 자동 갱신됐다는 증거는 아닙니다. 자동 반영을 시험하지 않았다면 미검증으로 표시합니다.

사용자가 동일 세션의 갱신 검증을 요청하거나 플러그인 출시 전 해당 동작을 검증할 때만 [업데이트 반영 검증](update-verification.md)을 읽습니다. 이 검증은 선택형 수동 통합 검사이며 일반 업데이트마다 실행하지 않습니다.

이 절차는 현재 프로젝트와 로컬 Codex의 WOMC 설치만 바꾸며 원격 저장소를 수정하지 않습니다. 커밋·푸시는 사용자가 별도로 요청했을 때만 수행합니다.
두 `codex plugin` 명령은 Windows, macOS, Linux에서 동일하게 실행합니다. 플러그인 루트는 설치 결과에서 확인해 경로 구분자를 하드코딩하지 않고, 생성기는 현재 환경에서 사용 가능한 Python 실행 파일로 실행합니다.
