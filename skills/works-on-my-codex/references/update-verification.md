# 업데이트 반영 검증

설치본 갱신, 프로젝트 하네스 갱신, 실행 중인 세션의 자동 반영은 서로 다른 결과다. 파일이나 설치 버전만으로 세 번째 결과를 통과 처리하지 않는다.

## 일반 업데이트에서 확인할 것

- `codex plugin list --json`에서 WOMC의 설치 버전·활성화 상태·설치 경로를 확인한다.
- 확인한 설치 경로의 `SKILL.md`와 생성기를 사용한다. 소스 저장소나 이전 캐시 경로로 대체하지 않는다.
- 하네스 생성에 사용한 동일 인수에 `--check`를 추가해 성공 종료를 확인한다. diff에서 사용자 지침 보존도 확인한다.
- 결과에 설치본, 하네스, 세션 자동 반영을 따로 적는다. 실제로 확인하지 못한 항목은 미검증과 이유를 적는다.

## 선택형 수동 통합 검사: 실행 중인 CLI 세션

Codex CLI 0.154.0에는 외부 플러그인 갱신 후 기존 세션의 스킬·도구를 갱신하는 수정이 포함됐다. 다른 앱이나 버전의 동작까지 이 검사로 보장하지 않는다. 근거: [공식 변경 기록](https://learn.chatgpt.com/docs/changelog).

사용자가 실제 검증을 요청한 경우에 실행한다. 플러그인 설치 설정 변경과 계정·네트워크를 사용하는 모델 실행을 포함하므로, 출시 작업에 이 검증이 명시적으로 포함되지 않았다면 먼저 해당 실행 범위의 승인을 받는다. 일반 소스 수정이나 로컬 단위 테스트 요청만으로 실행하지 않는다.

1. 지원되는 CLI 버전을 확인하고, 두 플러그인 버전 간 실제 변경 사항 중 스킬 발견 정보로 확인할 수 있는 항목을 고른다. 이전 버전과 새 버전의 이름·설명 차이가 없다면 별도의 격리된 시험용 플러그인을 사용한다. 실제 WOMC에 시험 문구를 넣거나 사용자 설치본을 강제로 내리지 않는다.
2. 이전 설치본이 로드된 CLI 세션을 유지한다. 세션 식별자, CLI 버전, 플러그인 버전과 현재 제공된 스킬 목록의 해당 항목을 기록한다.
3. 별도 터미널에서 승인된 플러그인 갱신을 실행한다. 설치 목록에서 새 버전과 경로를 확인한다.
4. 기존 세션의 다음 턴에서 현재 제공된 스킬 목록의 변경 항목을 확인한다. 정답 문구를 프롬프트로 알려주거나 새 `SKILL.md`를 직접 읽게 하지 않는다. 발견 목록을 확인할 수 없거나 새 파일을 직접 읽어야만 답할 수 있다면 자동 반영은 미검증이다.
5. 세션을 새로 만들거나 재개하지 않은 상태에서 변경 항목이 새 버전과 일치해야 동일 세션 반영 통과다. 이전 내용이 유지되면 실패, 비교 가능한 증거가 없으면 미검증으로 기록한다. 새 세션에서 확인한 결과는 새 세션 로드 결과로 별도 기록한다.

WOMC는 MCP 도구를 제공하지 않으므로 이 검사로 도구 목록 갱신까지 통과했다고 보고하지 않는다. 기존 `tests/test_codex_integration.py`는 새 임시 실행에서 프로젝트 지침을 읽는 검사이며, 동일 세션 플러그인 갱신 검사를 대체하지 않는다.

## 결과 기록

| 대상 | 결과에 포함할 증거 |
|---|---|
| 설치본 | 버전, 활성화 상태, 실제 설치 경로 |
| 프로젝트 하네스 | 대상 경로, `--check` 종료 코드, diff 검토 결과 |
| 동일 세션 스킬 반영 | 세션 식별자, CLI 버전, 변경 전후 항목, 통과·실패·미검증 |

검사 기록은 해당 작업의 결과 보고에 남기며 프로젝트 `AGENTS.md`에 누적하지 않는다.
