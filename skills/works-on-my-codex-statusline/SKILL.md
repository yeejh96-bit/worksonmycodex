# WOMC 상태 표시줄

Codex TUI 하단을 다음과 같이 지원되는 항목 순서로 설정합니다.

```toml
status_line = ["model-with-reasoning", "weekly-limit", "context-remaining", "project-name"]
```

화면에는 `모델 + 추론 수준 -> 권한 모드 -> 주간 잔여량 -> 컨텍스트 잔여량 -> 프로젝트 이름` 순서로 나타납니다. Codex는 `Full Access` 같은 권한 모드를 자동으로 넣으므로 `tui.status_line`에서 선택하는 항목이 아닙니다. `weekly-limit`와 `context-remaining`은 사용량이 아니라 남은 비율이므로 사용한 비율로 설명하지 않습니다.

이 설정은 프로젝트 규칙이 아니라 사용자의 Codex `config.toml`에 저장되는 개인 UI 설정입니다. 신뢰된 WOMC `SessionStart` 훅은 기본값을 한 번만 조용히 적용하고 성공 여부를 `PLUGIN_DATA`에 기록하여 이후 사용자 설정을 덮어쓰지 않습니다. Codex가 훅보다 먼저 설정을 읽으므로 처음 훅을 신뢰해 실행한 뒤에는 새 세션을 한 번 더 시작해야 할 수 있습니다. 훅을 신뢰하지 않았거나 플러그인 호스트가 훅을 실행하지 않는다면, 사용자가 이 스킬을 명시적으로 호출하거나 변경을 요청했을 때만 설정합니다.

`scripts/configure_statusline.py`는 이 `SKILL.md`를 기준으로 찾습니다. 먼저 `--apply` 없이 실행합니다. 비공개 MCP나 환경 설정이 포함될 수 있는 나머지 구성은 출력하지 말고, 대상 경로와 상태 표시줄 항목의 정확한 변경만 보고합니다.

사용자 수준 설정을 쓰면 모든 Codex 프로젝트에 영향을 줍니다. 현재 요청이 이 범위를 명시적으로 승인하지 않았다면 `--apply`로 다시 실행하기 직전에 승인을 받습니다. 이미 승인했다면 바로 적용합니다. 스크립트는 관련 없는 내용을 보존하며 모호한 인라인 테이블, 중복 섹션·키, 여러 줄 `status_line` 값은 수정하지 않습니다.

적용 후 `codex --strict-config --version`으로 검증합니다. 사용자에게 새 Codex 세션을 시작하라고 안내합니다. 기존 대화형 TUI에서는 `/statusline`으로 다시 불러오거나 선택을 조정할 수 있습니다. 계정에서 해당 사용량 제한 기간을 제공하지 않으면 Codex가 주간 한도를 생략하므로 반드시 표시된다고 말하지 않습니다. 터미널 폭이 매우 좁으면 뒤쪽 항목이 생략될 수 있으므로 기본 순서를 바꾸기보다 터미널 폭을 넓히는 방법을 우선합니다.
