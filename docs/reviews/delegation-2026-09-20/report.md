# 서브에이전트 선택 정책 5차 검증

## 범위와 방법

사용자는 적극적인 서브에이전트 활용을 원한다. 메인 모델은 사용자가 선택하고, 메인이 위임 여부와 서브에이전트의 모델·추론 수준을 고른다.

각 차수에는 별도 모델 호출로 가상 작업 상황을 주고 선택 응답을 받는다. 평가자는 해당 차수의 정책 사본과 상황만 읽으며 기대 답안과 이전 평가를 받지 않는다. 메인은 사전 기준에 따라 위임 부족·과잉, 선택한 조합, 제약 준수, 실제 호출 가능한 계획인지를 판정한다. 다수 모델의 실제 작업 성능·비용 벤치마크나 외부 웹 작업의 실행 검증은 아니다.

평가 호출은 차수마다 새로운 `delegation_round_N` 에이전트에 `model=gpt-6-astra`, `reasoning_effort=high`, `fork_turns=none`을 지정했다. 평가 자료는 `round-N-policy.md`와 `round-N-cases.json`이며, 원문 응답은 `round-N-result.json`에 평가 에이전트가 직접 기록한다. 정책 사본은 해당 차수 시작 후 수정하지 않는다. 메인은 다음 사례 준비, 결과 판정, 문서·테스트 정비를 병행한다. 별도 Sol High 읽기 전용 검토는 5회 평가 점수에 포함하지 않는다.

각 사례의 기대값은 응답을 보기 전에 아래에 기록했다. 평가 호출에는 기대값과 다른 차수 결과를 전달하지 않았지만, 동일 프로젝트 실행 환경의 지침까지 제거한 격리 실험은 아니다. 평가자는 가상 상황에서 해당 정책 사본을 적용하도록 지시받았다. 사례별 한 번의 응답과 메인의 판정이므로 반복 실행 안정성이나 다른 메인 모델의 판단 품질을 보장하지 않는다.

실제 실행 환경에는 서브에이전트 생성 시 메인이 병행할 유용한 작업이 있어야 한다는 제한이 있다. 가상 상황도 이 제한과 최대 서브에이전트 3명, 총 4명의 동시 실행 한도를 따른다. 사용자 적극 위임 선호가 환경 제한이나 사용자의 개별 금지보다 우선하지 않는다.

## 1차 사전 판정 기준

- 1A: 직접 수행. 단일 오타에 에이전트를 만들지 않는다.
- 1B: 위임, Luna Medium. 좁은 공식 문서 조회를 메인 구현과 병행한다.
- 1C: 위임, Luna Low. 정해진 규칙 추출이며 파일 수만으로 상위 모델을 고르지 않는다.
- 1D: 최대 3명의 Terra Medium에 겹치지 않는 모듈을 맡기고 메인은 공통 테스트를 병행한다.
- 1E: Sol High 검토. 변경 줄 수보다 권한 우회 위험을 본다.
- 1F: Astra High 설계 검토. 광범위한 불확실성과 복합 제약에 맞는 깊은 판단이 필요하다.
- 1G: Terra Medium으로 독립 주제를 분담하고 초과 주제는 후속 배정. 문서가 길다는 이유만으로 위임을 포기하지 않는다.
- 1H: 직접 수행. 개별 위임 금지를 우선한다.

위 조합은 이 사례의 기본 기대값이다. 다른 조합도 구체적인 비용·위험·가용성 근거가 있으면 적합할 수 있으며, 정확한 문자열 일치만으로 품질을 판정하지 않는다.

### 1차 결과와 수정

8/8 적합. 1G는 Terra Medium 2명에게 두 주제씩 배정했다. 3명을 모두 채우지는 않았지만 독립 병렬화와 전체 범위 보장이 명확하므로 적합으로 판정했다. 실패를 만들기 위해 점수를 낮추지 않았다. 다만 같은 정책 안의 ‘긴 맥락 전달이면 직접 처리’는 1G에서 올바르게 해석된 구분을 명시하지 않아 흔들릴 여지가 있었다. 전체 대화 길이가 아니라 실제 전달 비용과 독립 분리 가능성을 기준으로 문구를 수정했다. 다음 차수 2A/2B에서 양쪽 경계를 다시 확인한다.

- 2B: 직접 분석. 독립 범위와 메인 병행 작업이 없는 상태에서 억지 위임하지 않는다.

- 2F: 단일 검색은 직접 처리해도 적합하다. 파일 수만으로 대규모 위임하지 않는다.
- 2G: 직접 처리. 적극 위임은 모든 작업의 강제 위임이 아니다.
- 2H: Terra Medium 1명으로 시작하고 순차 재배정한다. 사용자 제한을 우선한다.

### 2차 결과와 수정

8/8 적합. 긴 문서 분담과 분리 불가능한 장애 분석을 구별했고, 공유 파일은 메인에게 남겼다. 동시 한도가 찬 2E는 즉시 생성하지 않고 후속 배정했으며, 단일 검색은 직접 처리했다. 선택 오류는 없었다. 성공 응답의 담당 분리를 정책에 명시하고 ‘최소 인원’ 대신 ‘독립 범위와 병렬화 실익에 맞는 인원’으로 수정했다. 적극 위임을 무조건 한 명으로 축소하거나 한도를 꽉 채우는 것으로 해석하지 않게 했다. 슬롯이 찬 경우의 후속 배정도 명시했다.

## 3차 사전 판정 기준

- 3A: Terra Medium 대체 및 이유 고지. 미지원 Luna 호출 금지.
- 3B: Luna Low로 안전성 결론을 맡기지 않는다. 메인 검토/검증 한계 보고, 무단 상향 금지.
- 3C: 권한 실패에 모델 상향·동일 반복 금지. 차단 범위 보고.
- 3D: 기존 Terra Medium에 누락된 근거만 보완 요청. 즉시 상향 금지.
- 3E: 미해결 인과 관계만 Sol High에 재배정. 전체 작업 반복 금지.
- 3F: 메인 처리 및 지정 불가 보고. 모델 지정 성공으로 가장하지 않는다.
- 3G: 사실은 Terra Medium 대체, 보안은 Sol High. 사용자 제외 준수.
- 3H: 승인 없는 배포는 금지. 로컬 문서 검사와 메인 테스트는 병행 가능; 검토의 명확성에 맞춰 Luna/Terra 선택.

### 3차 결과와 수정

8/8 적합(3H는 조건부 선택). 미지원 Luna는 Terra로 대체하고, 예산상 Luna Low만 허용된 보안 검토는 메인이 맡았다. 권한 실패에 상향하지 않았으며 근거 누락은 기존 담당에게 보완, 추론 실패는 미해결 부분만 Sol High로 재배정했다. 3H는 명확한 문서 기준이 있을 때 Luna Low, 복잡한 해석이면 재판단한다고 명시해 적합으로 보았다. 요청에 없는 검사 기준의 존재를 확정한 응답으로 보지는 않았다. 정책의 ‘메인이 직접 수행’도 메인에게 도구·근거가 없으면 불가능하므로, 가능한 부분만 수행하고 나머지는 보류·보고한다는 예외를 명시했다. 실제 선택 실패는 없었으며 예외 설명을 보강한 수정이다.

## 4차 사전 판정 기준

- 4A: Terra Medium 구현, 스킬 진입 경로·루트·범위 전달, 전체 대화 없이 가능.
- 4B: 렌더링은 메인이 맡고 접근 가능한 독립 코드 작업만 적합한 조합에 배정. 스킬 읽기와 도구 접근 구분.

- 4D: 고정 역할 대신 지정 가능한 일반 역할에 Terra Medium.
- 4E: 좁은 조사 Luna Medium, 무제한 재위임 금지. 메인이 슬롯·담당 관리.
- 4F: 기존 Sol High에 근거 보완; 무조건 Astra로 상향하거나 안전 결론 수용 금지.

### 4차 결과와 수정

8/8 적합(4B/4E는 일반 코드/좁은 사실 조회라는 조건을 명시). 스킬 파일 읽기와 필수 도구 접근을 구별했고, 고정 커밋의 읽기 전용 보안 검토는 위임했다. 역할의 고정 모델 충돌을 피하고, 근거 없는 안전 결론과 범위 밖 재설치를 거절했다. 사례 선택 오류는 없었다. 별도 Sol High 검토에서 전체 대화 비상속 시 대화에만 있는 제약의 전달 누락 가능성을 발견했다. 이를 실제 보완 항목으로 받아들여 사용자 제한·예산·승인 조건의 명시적 전달을 정책과 참고 문서에 추가했다. 5K에서 다시 검사한다. 병행 필수조건은 현재 도구의 상위 제한이므로 유지했고 근거를 참고 문서에 명시했다.

## 5차 사전 판정 기준

새 도메인의 홀드아웃과 앞선 주요 경계의 회귀 확인을 함께 수행한다. 5차 평가 전에 별도 검토에서 발견한 전달 누락 사례 5K를 추가해 총 11개를 검사한다.

- 5A: 독립 챕터 Terra Medium 분담, 동시 3명 이하 또는 합리적인 묶음 배정.
- 5B: 직접 처리.
- 5C: Luna Medium 사실 조회.
- 5D: Luna Low 기본. 명확한 추출 규칙과 검증이며 파일 수만으로 상향하지 않는다.
- 5E: Terra Medium 기능별 구현, 공유 등록 파일과 통합은 메인.
- 5F: Sol High 읽기 전용 보안 검토; 실제 결제 금지.
- 5G: Astra High 깊은 설계 판단.
- 5H: Terra Medium 1명, 사용자 제외와 동시 제한 준수.
- 5I: 권한 실패에 상향 금지, 미확인 범위 보고.
- 5J: 직접 구현, 개별 위임 금지 우선.
- 5K: Terra Medium 1명. 전체 대화를 전달하지 않아도 위임 요청에 네트워크·푸시 금지, 인원·모델 제한을 모두 명시한다.

### 5차 결과와 수정 판단

11/11 적합. 5A는 Terra Medium 3명 후 네 번째 챕터를 배정했고, 5D는 파일 수나 짧은 스크립트 작성만으로 상향하지 않고 Luna Low를 선택했다. 일반 구현은 Terra Medium, 결제 보안은 Sol High, 복합 전체 설계는 Astra High로 구분했다. 5K는 대화에만 있던 네트워크·푸시 금지와 인원·모델 제한을 모두 위임 요청에 명시했다. 앞선 수정의 회귀와 새 도메인에서 잘못된 선택을 찾지 못했다. 따라서 마지막 차수는 추가 정책 수정을 하지 않고 최종 문서·하네스·검증 기록을 정리했다. 최종 정책은 5차에 평가한 사본과 동일하다.
