### 서브에이전트 위임

- 메인 모델·추론 수준은 사용자가 선택한다. 아래 기준은 서브에이전트에만 적용하며, 사용자가 정한 모델·위임 제한·예산을 우선한다.
- 사용자는 서브에이전트의 적극적인 활용을 선호한다. 메인은 작업마다 분리 가능한 조사·구현·검토를 먼저 찾고, 범위와 완료 기준이 분명하며 다른 유용한 일을 병행할 수 있으면 직접 모두 처리하기보다 위임을 우선한다. 전체 요청이나 대화가 길어도 필요한 맥락을 독립 범위로 나눌 수 있으면 위임한다. 짧은 단일 작업, 맥락을 분리하기 어려워 전달 비용이 이득보다 큰 작업, 결과를 기다리는 동안 병행할 유용한 일이 없는 작업은 직접 처리한다.
- 작업 이름보다 모호성·오류 영향·검증 난도를 보고 아래 조합을 선택한다. 웹 조사라는 이유만으로 낮은 수준을 고르거나, 모든 일을 최고 수준에 맡기지 않는다.

| 위임 작업의 성격 | 모델 | 추론 수준 |
| --- | --- | --- |
| 기준이 명확한 추출·분류·파일 위치 탐색 | `gpt-5.6-luna` | `low` |
| 질문과 출처 범위가 좁은 웹 조사·공식 문서 사실 확인 | `gpt-5.6-luna` | `medium` |
| 여러 출처 비교·코드 경로 추적·독립적인 일반 구현과 테스트 | `gpt-5.6-terra` | `medium` |
| 상충하는 근거 해석·복잡한 원인 분석·보안 및 중요한 변경 검토 | `gpt-5.6-sol` | `high` |
| 여러 영역에 걸친 모호한 설계로 별도의 깊은 판단이 꼭 필요한 작업 | `gpt-6-astra` | `high` |

- 현재 위임 도구가 지원하는 모델·추론 조합과 필요한 도구 접근을 확인하고, 선택한 두 값을 실제 호출 인수로 지정한다. 프롬프트에 이름만 쓰는 것은 모델 선택이 아니다. 사용자 정의 에이전트의 고정 설정과 충돌하면 그 역할을 쓰지 않는다. 도구가 모델 변경과 전체 대화 상속을 함께 지원하지 않으면 필요한 맥락만 전달한다.
- 요청에는 목표·완료 기준, 프로젝트 루트·담당 파일과 읽기/수정 범위, 필요한 스킬의 이름·진입 경로, 확인된 사실·미확인 사항을 담는다. 서브에이전트도 적용되는 프로젝트 지침과 해당 스킬을 읽고 따른다. 스킬·필수 도구에 접근할 수 없으면 추측하지 않고 메인에 알린다.
- 독립 범위와 병렬화 실익에 맞는 인원을 배정하고 사용자·실행 환경의 동시 한도를 따른다. 한도가 차면 새 작업은 기존 작업 완료 후 배정한다. 같은 일을 중복 수행하거나 같은 파일을 동시에 수정하지 않도록 담당을 나누고, 공통 연결 파일과 통합은 메인 또는 한 담당자가 맡는다. 서브에이전트는 재위임이 별도로 배정되지 않으면 직접 수행한다. 기존 승인 경계는 그대로 적용한다.
- 근거·테스트·미확인 사항을 결과에 포함한다. 근거 부족이면 질문을 좁히고, 추론 난도가 원인이면 해당 미해결 부분만 적합한 상위 조합으로 재배정한다. 권한·도구·접속 실패는 모델을 올려 해결하려 하지 않는다. 같은 원인으로 반복 위임하지 않는다.
- 지원되지 않는 조합은 요구 품질을 충족하는 사용 가능한 조합으로 바꾸고 이유를 알린다. 적합한 대안이나 모델 지정 기능이 없으면 메인이 직접 수행하고 제한을 보고한다. 모델 상속을 지정 성공으로 보고하거나 설정·권한을 우회하지 않는다.
- 메인은 위임 때 담당·모델·추론 수준·이유를 짧게 알리고, 반환된 근거와 변경분을 검토해 통합·최종 검증·보고를 책임진다. 작은 작업에 위임 판단표를 매번 출력하지 않는다.
